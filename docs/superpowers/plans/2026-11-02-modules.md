# Modules, Install Modes and Intake Station Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every filament-kit part a selectable module, chosen by install mode (server / station / all-in-one / custom) at install and changed later in `filament-kit config`, and port the filament-ops intake station in as the `station` module.

**Architecture:** `modules.py` is the registry and mode resolver. `modules apply` turns `config.json` into a list of `Action`s (pure, tested) and an executor runs them as root; `install.sh` shrinks to a bootstrap that ends in `apply`, and the config menu ends in the same `apply`. Unit files and helper scripts are copied to `/opt/filament-kit/resources/` at install, so `apply` works later without the tarball. The station is a separate process (`python -m filament_kit.station`) under its own user.

**Tech Stack:** Python ≥3.12 (Starlette, uvicorn, pytest), bash, systemd, nfcpy 1.0.4, pyserial, ALSA `aplay`.

**Spec:** `docs/superpowers/specs/2026-11-02-modules-design.md`

## Global Constraints

- Ubuntu ≥ 24.04 (tested on 26.04); native systemd + venvs, no Docker.
- Missing `modules` in `config.json` = the **server** mode = today's kit; an upgrade asks nothing and changes no behaviour.
- Spoolman is never in the package: fetched by `install/spoolman.sh`, pinned `v0.27.0`, SHA-256 `bcc961af4c20d7ad7f1740f5609cd3efd94c4556baafaeba5036122dd7e46704` (moved verbatim from install.sh).
- Never delete data when a module is turned off; only `uninstall.sh --purge` deletes.
- No nftables/ufw changes. `IPAddressAllow` for the station = `localhost` + single addresses from `station.allow`; never a range.
- Station HTTP stays read-only; `/state` and `/last-tag` shapes identical to filament-ops `station/intake_station.py`.
- Off-module routes answer `409 {"error": "module_off", "module": "<name>"}`.
- Secrets: the API key is only typed by a person at a terminal (hidden), stored `root:filament-kit 640`.
- GPL-3.0-or-later headers/licence as the repo already has; they/them in docs.
- Tests: `cd server && .venv/Scripts/python -m pytest` (Windows) or `.venv/bin/python -m pytest` (WSL). Linux-only code paths (hidraw `select`, systemd) are tested through pure functions and fakes, and end-to-end on WSL in Task 7.
- Commits: only when the owner asks; each commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. The "Commit" steps below are staging points; batch them into commits when the owner says so.

## Review Focus

1. **Existing family install upgrades** (config without `modules`): the apply plan must equal today's install (spoolman, filament-kit, build.path, library.timer, backup.timer; no station user, udev, brltty or suspend changes). → Task 3 `test_legacy_config_plans_todays_install`.
2. **Station mode given a server name that does not resolve**: apply stops with a `fix:` line and writes no drop-in (not an empty or wide allow list). → Task 3 `test_station_unresolvable_server_fails_before_writing`.
3. **Mode switch all-in-one → station**: Spoolman/server units are disabled, but no action removes `/var/lib/spoolman`, `/var/lib/filament-kit` or `/etc/filament-kit`. → Task 3 `test_switch_never_removes_data`.
4. **A range in `station.allow`** (`192.168.1.0/24`, `0.0.0.0`, `::`): rejected by validation. → Task 1 `test_station_allow_rejects_ranges`.
5. **`filament-kit status` on a station-only machine**: no key, certificate, Spoolman or API failures; only the station service line. → Task 5 `test_status_station_only`.
