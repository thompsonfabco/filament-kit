# filament-kit 0.5.3

Upgrade the server with `sudo filament-kit update`.

## What's new

### Intake history: revise, edit and undo

Every spool you save at intake now leaves a record on the server: the label photos, the values you saved, the weight and
the tag. Open it later to correct a wrong read without scanning the spool again.

- **Edit by hand**, or **ask the AI to correct it** with a note such as "brand is Polymaker". The values before and after
  are shown, and nothing is written until you accept.
- **Undo revision** takes back the newest correction, one step at a time. A correction never edits a filament that other
  spools also use: the spools move to a filament with the new values instead. Each spool keeps its tag, opened state,
  location and used weight.
- It is on the setup page (**Intake** tab), in the phone web app (**History** tab), in the Android app and on the command
  line (`filament-kit intake history | show | revise | edit | undo`).
- The newest 20 records are kept by default; **Intake records kept** in the settings changes that (0 to 500). Records are
  part of the backups. Only a correction made with Claude counts toward the daily label-read limit.

### Flash a device: no toolchain needed

The Printer Station and the intake panel (ESP32-C3 boards) are written from ready-made firmware that comes with the kit.

- **Setup page, Flash a device tab.** Write a board plugged into the computer you sit at (Chrome or Edge on a desktop or
  laptop, setup page opened over HTTPS) or one plugged into the server. Type the Wi-Fi name and password and pick the
  buzzer; the page ends with "Done. The Printer Station joined ... and reached the kit.", or with what to fix.
- **Command line:** `sudo filament-kit reader setup` asks the same questions. Run it again to update a reader later.
- The buzzer trigger (high or low) is a setting; **high-triggered is the default**. A reader built with the older 3-pin
  buzzer module needs **low** (`--buzzer low`, or the choice on the Flash a device tab).
- The Printer Station no longer speaks. Its beeps and its display are unchanged.

### Local label reading (kit side)

The kit can send label photos to a label reader on your own network instead of to Claude, so nothing leaves your home.
Turn it on with `sudo filament-kit modules enable local_intake`; it can run beside the Claude reader. The setup page and
the command line (`sudo filament-kit local-intake install | plan | remove | token`) show what an install needs, install the reader
from its signed release, upgrade it and remove it. The phone web app and the Android app say which reader answered and
how sure it was. A correction from the intake history can use the local reader too.

**The reader module itself (`filament-kit-vision`) is not released yet.** Until it is, the install finds nothing to
download, and only a reader you already run yourself can be pointed at.

### Presets and phones

- **Accept preset updates and restore deleted presets from the Android app and the phone web app**, not only from the
  command line. The Android app's Home screen has **Build now**.
- A Klipper printer can be added from the phone web app's Printers tab and from the Android app's Printers screen. The
  phone web app lists printers by family, with the secret fields inline.
- The Android app asks once to trust a changed printer or server certificate from a single notice, and the connection
  probe is faster.

### Fixes you may have seen

- **A Klipper printer (an SV08 MAX in the report) showed "Reconnecting..." and "no such printer"** under Usage and Slots in
  the phone web app while the setup page showed it connected. Its pages work now.
- **Mapping slots on an X2D or P2S that refused the first job file:** the calibration job now tries the other job file once,
  and the printer keeps the file it answered. The report includes how each attempt ended.
- The calibration log names a printer by its name, never its serial number.
- A Klipper spool you moved while Spoolman was down is retried instead of being lost; a deleted spool no longer stops the
  lanes from being published.

## Removed

- **Nightly builds are gone.** Releases come from the main branch as before; there is no nightly channel to switch to.
- **The migrations from the old filament-ops and scanner projects** (`filament-kit migrate-ops`, `migrate-scanner` and
  the old scanner token restore mode of a backup) are gone, with their guide.
- **The `slot_service` setting is gone.** The connector's `printer_slots` and `printer_set_slot` tools always use the
  kit's own printer connection (the `printers` module must be on). The older connector tools `h2d_slots` and
  `h2d_set_slot` are removed: a Claude connector that learned them now gets "unknown tool"; use the two tools above. There
  is nothing to do by hand for the old slot token file; `modules apply` takes the web service's read permission off it.

## Behaviour changes

- **Forgetting a printer's pinned certificate now needs its Access Code**, on the setup page and with
  `filament-kit printer unpin`, like the paired-device API already did.
- **Printer names are unique.** Adding a Bambu printer under a name another printer has makes it "name 2" and so on, so
  slot locations in Spoolman stay distinct.
- **`reader setup --source` asks before it flashes a lone ESP32 board** and refuses a board that answers as the intake
  panel. It stops the station while it probes the port.
- **An expired web certificate is served with a warning** when it is the only pair left, instead of leaving the web server
  down. The log line says to renew it (`sudo certbot renew`).
- **Order matching needs the Claude reader.** The `orders` module now depends on `ai_intake` even with the local reader
  on, because the order history goes only into Claude's prompt. The setup page and `modules enable` say so.
- A label read that never reached Claude is given back to the daily limit.
- Only `http` and `https` redirects are followed when the kit fetches a tag source, and a body that is too large is
  refused.

## Other fixes from the full review

Small fixes in groups; none needs a setting changed.

- **Printers and mapping:** stopping a mapping with nothing running no longer spoils the next one; a manual map expires;
  printer reports are ordered by time; Bambu warnings read as plain sentences; the SSDP serial check is capped.
- **Klipper:** scan lists a Moonraker that wants an API key; lanes are removed when the module is turned off or shrunk; a
  stopped job's grams are scaled by the filament used; only MJPEG webcams are offered; a cut-off reply shows Offline.
- **Presets and library:** an empty system-preset upload is refused; a library update you rolled back stays rolled back
  against scheduled updates; colour and temperature are checked before a vendor is made; builds are faster.
- **Usage tracking:** 3MF files are read safely, a damaged one is logged, and the undo is written before the credit.
- **Station, panel and reader:** the scale reports kg and mg; the panel no longer blinks offline after long uptime; the
  reader retries its lists every 10 seconds and refreshes once before refusing a tap; the OLED re-probes.
- **Backups, web and PC sync:** the PC sync retries a folder while Bambu Studio is running, reads the pairing link without
  echo, and keeps the old key when a new certificate fails to install; the web page hides the public address until you
  give the code, and its touch targets and labels are larger.
- **Tools:** release and test scripts are pinned and stricter.

## Upgrading

Run `sudo filament-kit update`. Going back (`sudo filament-kit update --rollback`) returns to the previous signed
release. Check these after the upgrade:

- A Claude connector (or script) that used `h2d_slots` or `h2d_set_slot` must switch to `printer_slots` and
  `printer_set_slot`.
- If `orders` was on together with the local reader only, turn `ai_intake` on as well; `orders` refuses to switch on
  without it and says why.
- A Printer Station built with the older low-triggered buzzer module: when you next write its firmware, choose **low**.
- Forgetting a printer's certificate now asks for its Access Code; have it at hand.

## Not tried on real hardware

- Writing a Printer Station or intake panel from the browser (Web Serial), and from the server's USB port, was checked
  with test doubles only.
- The calibration retry for the X2D and the P2S was written from their printer reports; no X2D or P2S has run it.
- The local label reader's install and upgrade were checked against a fake release; the module is not published yet.
- The Printer Station's new buzzer default and the reader flash prompts were not run on a board with the older module.
