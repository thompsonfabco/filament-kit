# filament-kit 0.5.2

Upgrade the server with `sudo filament-kit update`.

## Fixes

- **Map slots on a Bambu Lab printer no longer fails at once after a failed or finished print.** When the printer's
  last job had ended (FAILED or FINISH), the kit could take that old state for the end of its own calibration job the
  moment it sent the print command, and report no mapping, or the last print's numbers. A calibration job now counts
  as started only once the printer shows it. Seen on an H2D; it applies to every Bambu printer the kit maps.
- **Map slots again with the same slot numbers as the last job is confirmed**, not reported as no mapping.
- A printer that never starts the calibration job now stops with "did not start" after 2 minutes, instead of ending at
  once with the old state.
- While a calibration job runs, the server log has one line per change of the printer's job state and codes, to make
  mapping problems easier to report. The values it logs are codes only, but each line names the printer by its serial number, so remove that before you post a log; `filament-kit printer report` is already cleaned.

## Upgrading

Run `sudo filament-kit update`. Going back (`sudo filament-kit update --rollback`) returns to the previous signed
release.
