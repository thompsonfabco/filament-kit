# Spoolwarden 0.6.1

Upgrade the Hub with `sudo filament-kit update`.

This is the first release since 0.5.4. It brings the redesigned Hub page, phone web app, Android app and command line,
four themes, and the new name: Spoolwarden was called filament-kit until now. The command is now `spoolwarden`; the
command `filament-kit` still works, runs `spoolwarden` and prints one line saying the name changed.

## What is new

### The new name

- **The product is called Spoolwarden** on the Hub page, in the phone web app, in the Android app, in the installer and
  update messages, in Slicer Sync and in the Klipper add-on.
- **The command is `spoolwarden`.** Install and update put it where `filament-kit` was. `spoolwarden --version` prints
  `Spoolwarden <version>`, and the help, messages and Fix lines name it. `filament-kit` runs `spoolwarden` with the same
  arguments, input, output and exit code, and prints one line on standard error saying the name changed. It is kept
  for a time and will be removed.
- **Folders, services and links keep their names** (`/etc/filament-kit`, `filament-kit.service`, the `filament-kit-sync`
  command and the project's address), so nothing on your Hub moves.

### The Hub page (the setup page)

- **One look, light or dark.** The page uses the shared colours, sizes, buttons and texts. A switch in the header picks
  Light, Dark or System (the default); the choice is kept in that browser.
- **A new shell.** A top bar and navigation: a side list on wide screens, and on a phone a bottom bar with a More sheet
  for the other sections. A lock chip in the header shows whether the page is unlocked and opens the unlock dialog; a
  right setup code costs no try, and a wrong one says how many tries are left.
- **Dialogs and results in place.** Dialogs replace the browser's own confirm and prompt boxes, the result of a button
  appears beside it with a short toast when something finishes, and long jobs show a job strip with the step they are on
  ("Step 2 of 3"), including when the Hub is restarting or not answering. Loading, empty, error and switched-off pages
  look the same everywhere. Logs wrap at every width.
- **Overview and Features:** Overview has summary tiles (printers, Tag Readers, recent additions) with a badge for what
  needs a look. Features can be turned on and off by name and say when a setting is needed first.
- **Printers:** each printer shows its state, with how many are connected or offline. You can test the connection, use a
  detected printer, dismiss it, see its slot mapping and collect a report (saved reports show once the page is
  unlocked). You can add a printer from the page: it can scan the Hub's own network for Klipper printers, and it offers
  the Klipper add-on's install commands to copy.
- **Settings:** regrouped. Network has a Remote access part; the Label Reader group shows whether a reader is installed
  on this machine, checks what an install or an upgrade needs, tests the reader and takes a reader token; Backups lists
  the backups with a download for each and sets how many days they are kept; Restore is a set of steps. A group saves at
  once and shows the last backup time, and an address you enter for the Hub can be tested before it is saved.
  The reader the Hub installs is called Spoolwarden Vision. If you have the earlier reader (`filament-kit-vision`)
  installed, Check and Upgrade in the Label Reader group replace it: the Hub removes the old service first, then
  installs the new reader, and it stops with a message if the old reader's uninstaller fails. Removing the reader takes
  away either one. A separate `filament-vision-server` install blocks the install until you remove it.
- **Devices:** paired devices (pair a phone, Slicer Sync or a Weigh Station; rename; revoke), Weigh Stations asking to
  pair, Tag Reader tokens and trusted computers.
- **Recently added:** the newest additions with the photo, what was added, when, where it came from, whether it was
  changed and how sure the Label Reader was, with a **To check** filter. One addition opens as a record: its photos, its
  values, **Edit by hand** with **Save changes**, and **Ask the Label Reader to correct it**, which shows a
  before-and-after list and waits for **Accept**. Every correction is listed with **Undo**.
- **Flash a device:** writes the firmware that comes with the Hub to a Tag Reader or a Weigh Station display over USB.
  You choose the device and where it is plugged in (this computer, or the Hub), press Connect and write, and see each
  step and its result. A Tag Reader's token is made only with the setup code, and writing through the Hub needs it too.
  A phone cannot flash a board over USB; the page says so and tells you to plug the board into the Hub or use a computer.
- **Slicer presets, Updates and Logs** are in the new look.
- **A reader that gives no per-field numbers** (the Cloud reader, for one) is shown as not rated instead of as sure.
- **QR codes are drawn by the Hub itself** (the pairing code and the phone web app's address, on the Hub page and in
  the terminal), so the `qrencode` package is no longer needed.
- **Long jobs report their steps:** backup, restore, update, rollback, applying features, a library update and its
  rollback, setting up a reader and pairing a Weigh Station print `==> step 2 of 3 ...` lines as each step starts.
  Setting up the Label Reader on the Hub no longer waits forever when the reader's own installer hangs: after 15
  minutes without output (or 4 hours in all) it stops, says so in the log and leaves the settings as they were.
- **Fixes:** the Trusted computers card no longer shows a stray `null` line, a failed read of the Weigh Stations asking
  to pair no longer shows an internal error name, the header name stays on one line on a 320 px phone, and the setup
  command box wraps instead of cutting the command.

### The phone web app

- **A new shell:** a top bar and a bottom bar (a side rail on tablets) with Add, Spools, Printers, Recent, Slicer presets
  and Settings; a More sheet holds the rest. A place whose feature is switched off says so. Sheets replace the
  browser's own boxes, and results and errors appear in place.
- **Add spools:** find a filament you already have or read the label photos, check each spool card with the Label
  Reader's confidence marks, Preview, then Add. An unfinished add is kept as a draft in that browser.
- **Spools:** the last tag read, a search that remembers Sealed only, and a spool sheet to link a tag and open the
  spool, update its weight, move it (with Undo), mark it empty or load it into a printer. Nothing is written that was
  not previewed.
- **Printers:** the printer list and one printer's page with its status, slots, filament used, slot mapping and
  settings.
- **Recently added:** each addition with its badges, where it came from and when; open one for its photos and fields,
  correct it by hand or ask the Label Reader, and undo a revision.
- **Slicer presets:** build the presets and see the result in place; add a new filament to a line or start a new line;
  Updates and Restore work as on the Hub page.
- **Home screen and offline:** the Add to Home Screen sheet lists the three iPhone steps (other browsers offer their
  own install). The app opens without the Hub; when the Hub does not answer it shows an Offline chip and a banner,
  tries again every 10 s, keeps the last data with "Last update <age>: the Hub did not answer.", greys what needs the
  Hub with "Needs the Hub." and says when it is connected again.

### Themes

- **A Theme choice** on the Hub page (Settings > Appearance), in the phone web app (Settings) and in the Android app
  (Settings > Appearance). The choice is kept on that device. Settings > Appearance on the Hub page also has a "Theme
  for new devices" field, and `spoolwarden config theme [<theme>]` shows or sets it; a device that has not chosen
  follows it, and a device that has chosen keeps its own.
- **Four themes**, each with a light and a dark side: Console (dense and technical, the default), Workbench (calm
  cards, a labelled side list on wide screens), Palette (colourful and roomy, a row of pills under the top bar on wide
  screens, lists as tiles) and Panes (a list of sections with the page beside it on wide screens, lists as plain rows;
  on a phone the page opens on the list of sections and Back returns to it).
- The Hub page, the phone web app and the Android app have all four, and the screens and routes are the same in every
  theme.
- **Opening a detail** (a printer, a spool, a recently added record, a preset line) follows the theme. Console opens it
  as its own page or screen. In Workbench the card expands in place on the Hub page and in the web app, and in the
  Android app on a tablet or wider (a phone opens its own screen). In Palette it slides in as a full-height sheet that
  returns focus to its row on close, closes on Back in the Android app, and shows only the current step of a numbered
  list open. In Panes only one detail is open at a time, beside the list on wide screens (with an empty-pane message
  until you choose one) and over it on tablets and phones, with Back in the detail's head on tablets and phones and
  Escape returning focus to the row on the web; Settings shows one group per pane.
- **Panes in the Android app** also shows a one-line summary under Printers, Recently added and Slicer presets in the
  list of sections, from data the app already holds.
- **Lists** that can be sorted show a "Sort by" label before their sort chips in Workbench, Palette and Panes (Console's
  table is unchanged).
- **A section switched off in Features** is dimmed in the Hub page's navigation in every theme, with a hollow circle in
  the side list of Workbench and Panes and a spoken ", switched off" for screen readers; it still opens its page,
  which says it is switched off.

### The command line

- **One vocabulary:** every command reports with the same state words, and a failure is `Error: ...` with a `Fix: ...`
  line. Waits longer than 2 seconds show progress; each command ends with a documented exit code; `--plain`, `--color`
  and `NO_COLOR` control the look for screen readers and pipes.
- **Destructive commands ask first** (forgetting a printer, unpairing a device, flashing a board, updating, rolling
  back, removing Spoolwarden). **Scripts need `--yes` from this version on:** without a terminal and without `--yes`
  such a command stops with exit code 2 and says so.
- **`--json` and `--quiet`** on every command that prints data or a result.
- **New command names** that match the Hub page: `printer`, `recent`, `devices`, `pair`, `presets`, `features`,
  `weigh-station`, `tag-reader`, `label-reader`, `catalog`, `config show` and `config set`. The old spellings still
  work; `spoolwarden help aliases` lists them, `spoolwarden help` prints the whole table, and `spoolwarden` alone
  prints the commands in groups. `recent edit` and `recent revise` count `--item` from 1, as the Hub page does
  (`intake edit --item 1` used to mean the second item, so change old scripts).
- **Menus with one set of keys:** `spoolwarden config` is the Hub page's Settings in the same groups; changes wait
  until `s` saves them. Printers and Features have their own screens.
- **Setup names:** `hub`, `weigh-station` and `hub-with-weigh-station` are accepted beside `server`, `station` and
  `all-in-one`, and `--hub` beside `--server` in `modules set` and `modules enable`. What is stored does not change.

### The Android app

- The app draws in the new look: Settings, pairing, Home, Printers, One printer (progress, controls, loading a spool,
  mapping by loading), Spools, Add spools (Photos, Check the spools, Preview, Done), Recently added and the Filament
  Catalog line. Its name and texts come from the shared catalogue.
- **Slicer presets screen:** the build status, a button to build now, the filaments without a preset line (add to a
  line or start one, with an optional Orca Slicer parent) and the product lines with Change parent.
- The printer and design texts are whole sentences, tapping a tag on Pick a spool picks that spool, taps made during a
  load are kept, and Replace this spool's tag is offered when the spool already has a tag.

### Slicer Sync and the Klipper add-on

- Their texts say Spoolwarden and name the `spoolwarden` commands. The `filament-kit-sync` command keeps its name.
- A paired phone can list the filaments that have no preset line, create a line, add filaments to a line, list the
  Orca Slicer parents a new line can use and ask for a build.

### Documents

- The README, the user guide and the install guides use the new names (Hub, Hub page, web app, Android app, Features,
  Weigh Station, Tag Reader, Label Reader, Filament Catalog, Slicer presets, Slicer Sync) and show the commands in their
  new spellings. The user guide's command table is the one `spoolwarden help` prints.

## Not finished yet

- The old command `filament-kit` is only a wrapper for now, and a later release removes it. Use `spoolwarden` in
  scripts.
- Folders, services, unit names and `filament-kit-sync` still carry the old name on disk.

## Upgrading

Run `sudo filament-kit update` on the Hub. Your installed command is still `filament-kit`, so type that one this time;
the update puts `spoolwarden` beside it. Afterwards `spoolwarden --version` prints `Spoolwarden 0.6.1`, and
`filament-kit` still answers, with its one-line note on standard error. Your spools, settings, key and paired phones
stay.

If you installed the 0.6.0 pre-release, run the same `sudo filament-kit update`: 0.6.1 is a release, so the update
finds it.

Scripts: add `--yes` to the commands that ask first (see The command line), and if you move `intake edit --item` to
`recent edit`, count the item from 1.
