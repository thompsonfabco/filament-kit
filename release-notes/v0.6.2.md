# Spoolwarden 0.6.2

Upgrade the Hub with `sudo spoolwarden update`.

A release of fixes for 0.6.1. Nothing else changed.

## Fixed

### Printers and slots

- **A spool assigned to an empty AMS slot is no longer lost.** In 0.6.1 the AMS cleared the setting when filament went
  in, so the slot stayed unset. The Hub now keeps the assignment and applies it once the AMS reports the slot loaded and
  read. It waits up to 15 minutes, and a newer assignment for the same slot replaces it.
- **A slot that is waiting says so.** In the phone web app the slot row reads "waiting for the spool to load in slot
  <slot>". On the Android app's printer page the slot row reads "Waiting for the spool to load", and tapping the slot
  shows "A spool is assigned to this slot and is applied when the slot loads." Before, it looked like an empty slot.

### The Hub page

- **Settings group summaries in the Panes theme are readable on wide windows.** In 0.6.1 the summary column was a few
  characters wide and each summary wrapped over many lines. The column is wider now.
- **The Hub's base address opens the Hub page.** `https://<hub>:8710/` showed "not found" in 0.6.1. It now shows the
  same page as `/setup`.

### Devices

- **A paired Weigh Station is listed as a Weigh Station.** This is so on the Hub page and in `spoolwarden devices`
  (new Type column), also for a station paired by an older version, which 0.6.1 listed as a bare "station". Its time
  reads "(last intake)", because a station calls the Hub only when it is used.
- **A Status column says whether the station answers** ("Answering" or "Not answering" on the Hub page; "answering" or
  "not answering" on the command line).

### Label Reader

- **The "On this Hub" install plan explains its sizes.** In 0.6.1 it showed a small download beside a much larger disk
  figure with no explanation. On the Hub page and in `spoolwarden local-intake plan` it now lists, in order, the required
  download ("Download now: <n> MB (required)."), what is also downloaded for the chosen hardware tier, and the disk
  used in total ("Disk used in total: <n> MB.").

## Known limits

- **A waiting slot is not shown everywhere in the Android app.** The Load screen's rows and the colour swatches in the
  printers list still show such a slot as empty.
- **A waiting assignment is kept in the Hub's memory.** Restarting the Hub drops it, and it ends after 15 minutes.
- **`/setup` is still the address the documents and printed texts give.** The base address is an addition.
- **The Status column needs the Weigh Station's address on the Hub** (the `station.url` setting). Without it the Hub
  cannot tell, and the column is empty. It is shown only when exactly one station is paired.
- **The second of the three size lines is the release's own description as text.** The release gives no size in MB for it, so it is
  not added into the total.

## Upgrading

Run `sudo spoolwarden update` on the Hub. Afterwards `spoolwarden --version` prints `Spoolwarden 0.6.2`. Your spools,
settings, key and paired phones stay. Going back (`sudo spoolwarden update --rollback`) returns to the previous
release.

The Android app updates itself from your Hub: after the update, the app's home screen shows **Update ready: Spoolwarden
<version>.** when this release carries a newer app. Tap **Install update**.
