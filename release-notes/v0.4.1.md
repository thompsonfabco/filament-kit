# filament-kit 0.4.1

Upgrade the server with `sudo filament-kit update`. The steps are at the end.

## What's new

### Klipper printers on the setup page

The setup page (`https://<computer name>.local:8710/setup`) now lists your Klipper printers whenever the `klipper`
module is on, even if the Bambu printers module is off. Each row shows the printer's name and its Moonraker address.

- **Test** asks Moonraker whether it answers and tells you Klipper's state. If Moonraker wants an API key, it says so.
- **Forget** removes the printer.
- A Klipper printer has no Access Code. Add printers with `sudo filament-kit klipper add "<name>" <host>`; the setup
  page does not add them.

### Intake station pairing

- `sudo filament-kit status` now shows the real pairing state of the intake station. Before, it said "station pairing
  not checked: run it with sudo" even when you had used `sudo`.
- `sudo filament-kit station pairing-state` prints the same answer on one line: `paired <address>:<port>`, `unpaired`
  or `unchecked`.

### Slot mapping on the X2D, and clearer results

- **X2D and P2S.** The calibration job now carries the printer settings the X2D and the P2S need (not yet confirmed on a
  real X2D or P2S; tell us how it goes). External holders and empty slots stay out of the job. A printer with no AMS
  unit maps without a job.
- **Old results and Developer Mode.** A mapping result from an earlier server run is labelled as old. A Developer
  Mode refusal clears on a new connection, and no longer greys out **Map slots**.
- **The app says what a result means.** **Slots mapped (n)**, **Slots mapped: confirmed for the loaded slots**,
  **Slot numbering not confirmed**, **Slot mapping failed**, and for a map that is out of date **Layout changed** or
  **Recent prints disagreed with the map**. **Map slots** is greyed only by the printer (not connected, or printing) or
  a running mapping.

### Safer home network access

- **Spoolman** answers only this computer and your home network (by default `localhost`, `192.168.0.0/16` and
  `10.0.0.0/8`), because it has no sign-in. If you use Tailscale or Docker, or Spoolman runs on another machine, add that
  network to `spoolman.allow` in `/etc/filament-kit/config.json`, then run `sudo filament-kit modules apply`.
- **The kit never replaces a Spoolman it did not install.** If one is already in `/opt/spoolman`, the install stops and
  says how to keep using it or let the kit replace the program.
- **The home-only web address's certificate lasts 825 days** instead of 30. `sudo filament-kit modules apply` makes a new
  one within 30 days of its end, `sudo filament-kit web status` warns before that, and the phone asks you to accept it
  again. A device that reaches the web address over IPv6 is now told why it was refused and what to change.
- **The servers no longer write request lines to the journal.** What is already in a journal stays there until it ages
  out.

### Licences

`THIRD-PARTY.md`, which the Android app shows under Settings > Licences (once you update the app), now lists each
component with its licence and attribution, nothing else. No licence changed, and the Android list now also includes
the app's transitive libraries.

## Fixed

- **`sudo filament-kit station pair` without a terminal.** Run from a script or with no keyboard attached, it used to
  stop with an error trace. It now says it needs a terminal, saves nothing and exits.

## Changed

- **Documentation.** The guides no longer say the repository is private: the one-command install and the Releases page
  need no GitHub account, and the steps for installing with a token are gone.

## Upgrading

1. **Server first.** Run `sudo filament-kit update`. Update the Android app to get the new Licences text.
2. **Intake station.** If `sudo filament-kit status` says the station is not paired, run
   `sudo filament-kit pair --station` on the kit server, then within 10 minutes `sudo filament-kit station pair` on the
   station computer and paste the link.
3. **Separate station computer.** Run `sudo filament-kit update` there as well.
4. **PC sync on Windows.** The installer is not code-signed, so Windows SmartScreen warns ("Windows protected your PC"):
   choose **More info**, then **Run anyway**. The user guide ("Pair your PC") has a one-line hash check for the download.
5. **Going back to 0.4.0** (`sudo filament-kit update --rollback`): nothing special is needed. The printer data file
   gained a `<slicer-project>` element and a job-file setting that 0.4.0 loads without error.
