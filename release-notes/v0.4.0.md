# filament-kit 0.4.0

## New

- **Setup page.** Enter what the installer doesn't ask for in a web page instead of the Terminal, at
  `https://<computer name>.local:8710/setup`. That covers:
  - the Anthropic key;
  - printers and their Access Codes;
  - the web passphrase and the library token;
  - pairing a phone, PC or station;
  - NFC reader tokens;
  - switching modules on or off.

  It works on your home network only, and every change needs the 8-digit **setup code**. The installer prints the
  code at a Terminal; `sudo filament-kit setup-code` shows it again, and `--new` replaces it. Too many wrong codes
  lock the page for a while; `setup-code --new` lifts the lock.
- **Load and unload from the iPhone web app.** The Printers tab can load a spool into a slot and unload it. It
  shows a dry run first and does the real change only after you confirm.
- **PC sync keeps every Bambu Studio current.** On Windows that is both stable (`%APPDATA%\BambuStudio`) and Beta
  (`%APPDATA%\BambuStudioBeta`); on Linux, the native, Beta and Flatpak folders.
  - One folder is the **primary**: its presets are sent to the server, and builds are made from them. It stays the
    same folder, whichever Bambu Studio you open last. To change it, set `"variant"` in the sync's `config.json`.
  - The other folders get every build too. Existing presets are never replaced in any folder.
  - `filament-kit-sync apply-updates --folder <folder> --all` takes the build's copy in one of the other folders
    when you want it (`--dry-run` first to see the list).
  - `"secondaries": false` keeps the old one-folder behaviour.
- **You can see when PC sync is waiting.** While Bambu Studio is open, `filament-kit-sync status` shows how long the
  sync has been waiting. After a day the log says so loudly. `sudo filament-kit status` shows "PC sync waiting for
  Bambu Studio to close since <date>".
- **Panels wired the other way round.** If your intake panel's yellow and red buttons and lamps are swapped, set
  `"panel_swap": true` under `"station"` in `/etc/filament-kit/config.json` and run `sudo filament-kit modules
  apply`. Panel firmware 9, which the station installs itself, gives both buttons a long press. With firmware 9,
  red acts when you release it.
- **Klipper printers.** A new opt-in `klipper` module connects filament-kit to Klipper printers through Moonraker.
  - **Adding printers.** Add one with `sudo filament-kit klipper add`, or find them with `klipper scan`.
  - **Where they show.** The app, web app, reader and Claude tools show their slots, spools, camera and usage next
    to your Bambu printers.
  - **Models.** Sovol SV08 MAX is verified; Sovol M1D is prepared but not yet verified.
  - **Spools follow the printer.** Loading a spool into a Klipper tool or lane updates Spoolman's location once the
    printer confirms it. Changes made on the printer itself (tag taps, the touchscreen, AFC or Happy Hare lane
    changes) update Spoolman too.
  - **Usage from Moonraker.** Moonraker deducts filament as it prints, and the kit logs each finished job. The
    printer status warns if Moonraker reports to a different Spoolman.
  - **Printer pack (optional).** `fk-printer-pack.tar.gz` adds the following on the printer, asking before every
    change:
    - per-tool spools for toolchangers;
    - a spool check at print start;
    - the active spool's load temperature;
    - an NFC reader (nfc2klipper);
    - the Moonraker settings.
  - **Spool Sync 2.0.0** for OrcaSlicer selects presets for every tool of a multi-tool printer.
  - **Editable printer data.** Klipper printer models live in `klipper_hardware.xml`, which you can override and
    the updater can refresh, like `bambu_hardware.xml`.
  - **Printer list file.** The printer list is now `printers.xml`. `printers.json` is still written beside it, so
    `update --rollback` to an earlier release keeps every Bambu printer.

## Fixed

- **NFC reader on the intake station.** Restarting the station service no longer leaves the PN532 reader not
  answering until it is unplugged. A reader left in that state is recovered on the next start.

## Changed

- **Separate web user.** The web app runs as its own user, `filament-kit-web`, with its state in
  `/var/lib/filament-kit-web`. It reaches the kit's data only through the kit, and the setup page is not reachable
  from it.
- **Order history.** Only the web app can read the order history now. Phones, PCs and the station can't.
- **Backups.** Backups keep file permissions. A restore must use `tar --acls --xattrs`, or be followed by
  `sudo filament-kit modules apply`. Restore into an empty folder.

## Upgrading

- **Order.** Upgrade the kit server first, then the PC sync. A PC sync that changes its primary folder needs the new
  server for that folder's first sync; with an older server it warns instead.
- **After the PC sync upgrade.** With Bambu Studio closed, the first run may log "Bambu Studio folder changed from
  ... to ...". That folder then syncs for the first time: its presets are uploaded as they are, and differing ones
  are listed as updates. See them with `sudo filament-kit profiles apply-updates --all --dry-run`, then apply them
  with `--all`. In the other folder, `filament-kit-sync apply-updates --folder <folder> --all` does the same when
  you want it.
- **Stations.** The station's panel firmware updates itself to 9. If you had set `STATION_PANEL_SWAP` by hand in a
  drop-in of your own, remove it and use `"panel_swap"` in the config instead.
- **Going back to 0.3.0.** If you go back within a day, the daily Claude read count starts over once.
