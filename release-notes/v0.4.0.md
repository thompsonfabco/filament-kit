# filament-kit 0.4.0

Upgrade the server first, then the PC sync. The upgrade steps are at the end.

## What's new

### Setup in a web page

You can now enter what the installer doesn't ask for in a web page instead of the Terminal: your Anthropic key, printers
and their Access Codes, the web passphrase, the library token, pairing a phone, PC or intake station, NFC reader tokens,
and switching modules on or off.

- Open `https://<computer name>.local:8710/setup` from a device on your home network. It does not answer anywhere else.
- Looking at the page needs nothing. Every change asks for the 8-digit **setup code**.
- The installer prints the code when you are at a Terminal. `sudo filament-kit setup-code` shows it again, and
  `sudo filament-kit setup-code --new` makes a new one.
- Too many wrong codes lock the page for a while. A new code lifts the lock.

### Klipper printers

Klipper printers that run Moonraker now work next to your Bambu printers. Turn on the new `klipper` module with
`sudo filament-kit modules enable klipper`, then add a printer with `sudo filament-kit klipper add "<name>" <host>`.
`sudo filament-kit klipper scan` finds printers on your network.

- The app, the phone web app, the NFC reader and Claude's tools show each printer's slots, spools, camera and usage.
- Loading a spool into a tool or lane updates its location in Spoolman once the printer confirms it. A change made on
  the printer itself (a tag tap, the touchscreen, an AFC or Happy Hare lane change) updates Spoolman too.
- Moonraker takes the filament off your spools while it prints. The kit logs each finished job, and warns in the
  printer's status if Moonraker reports to a different Spoolman.
- Sovol SV08 MAX is verified. Sovol M1D is prepared, but not yet verified.
- Printer models are in `klipper_hardware.xml`, which you can override and the updater can refresh.
- **Printer pack (optional).** `fk-printer-pack.tar.gz` installs extras on the printer and asks before every change:
  per-tool spools for toolchangers, a spool check at print start, the active spool's load temperature, an NFC reader
  (nfc2klipper), and the Moonraker settings the kit needs.
- **Spool Sync 2.0.0** for OrcaSlicer picks the filament presets for every tool of a multi-tool printer.
- Guide: `docs/klipper.md`.

### PC sync keeps every Bambu Studio up to date

If you have both the stable and the Beta Bambu Studio, the PC sync now keeps both current. On Windows that means
`%APPDATA%\BambuStudio` and `%APPDATA%\BambuStudioBeta`. On Linux it means the native, Beta and Flatpak folders.

- One folder is the **primary**. Its presets are sent to the server, and the server's builds are made from them. It
  stays the same folder whichever Bambu Studio you open last. To change it, set `"variant"` in the sync's `config.json`.
- The other folders get every build too. Presets that are already there are never replaced, in any folder.
- To take the build's copy in one of the other folders, close Bambu Studio and run
  `filament-kit-sync apply-updates --folder <folder> --all`. Add `--dry-run` first to see the list.
- To go back to one folder, set `"secondaries": false` in the sync's `config.json`.
- Presets the sync puts into the second Bambu Studio are local presets of that app. Its first sync with your account
  may create a second cloud copy of a preset with the same name, as with any preset you save by hand.

### You can see when the PC sync is waiting

The PC sync never changes presets while Bambu Studio is open. `filament-kit-sync status` now shows how long it has been
waiting, the log says so loudly after a day, and `sudo filament-kit status` shows "PC sync waiting for Bambu Studio to
close since <date>".

### Intake panels wired the other way round

If your panel's yellow and red buttons and lamps are swapped, set `"panel_swap": true` under `"station"` in
`/etc/filament-kit/config.json` and run `sudo filament-kit modules apply`. The station updates the panel to firmware 9,
which gives both buttons a long press. On firmware 9 the red button acts when you let go of it.

### Load and unload from the iPhone web app

The Printers tab can now load a spool into a slot and unload it. It shows what it will do first, and changes nothing
until you confirm.

## Fixed

- **Intake station reader.** Restarting the station no longer leaves the NFC reader (PN532) unresponsive until you unplug
  it. A reader left in that state is recovered at the next start.

## Changed

- **The web app has its own user.** It runs as `filament-kit-web`, with its files in `/var/lib/filament-kit-web`. It
  reaches the rest of the kit only through the kit server, and it cannot reach the setup page.
- **Order history.** Only the web app can read it through the server. Phones, the PC sync and the station cannot.
- **Backups and restore.** Backups now keep file permissions. If you restore one by hand, extract it with
  `tar --acls --xattrs` into an empty folder, or run `sudo filament-kit modules apply` afterwards.
- **Printer list.** The kit keeps its printers in `printers.xml`. `printers.json` is still written beside it, so
  `sudo filament-kit update --rollback` to an earlier release keeps your Bambu printers.

## Upgrading

1. **Server first.** Run `sudo filament-kit update`. Then update the PC sync (the new setup `.exe` on Windows, the new
   `install.sh` on Linux). A PC sync newer than its server logs a warning.
2. **Close Bambu Studio** so the PC sync can run. Its first run may log "Bambu Studio folder changed from ... to ...".
   That folder then syncs as if for the first time: its presets are uploaded as they are, and the ones that differ are
   listed as updates. See them with `sudo filament-kit profiles apply-updates --all --dry-run`, then apply them with
   `sudo filament-kit profiles apply-updates --all`.
3. **If you use both Bambu Studios.** Updates for the other folder are listed as "differing" and are not written on
   their own. When you want them, run `filament-kit-sync apply-updates --folder <folder> --all` on the PC. New presets
   still arrive there by themselves.
4. **Intake station.** The panel's firmware updates itself to 9. If you set `STATION_PANEL_SWAP` by hand in a service
   file of your own, remove it and use `"panel_swap"` in the config instead.
5. **Going back to 0.3.0** (`sudo filament-kit update --rollback`):
   - **What comes back.** The web app's Claude connector sign-ins, push subscriptions and its pairing come back as
     they were when you upgraded. 0.4.0 copies them to its new folder and leaves the originals in place. Anything you
     changed in them while on 0.4.0 stays behind in the new folder.
   - **Read count.** Going back within a day restarts the daily count of Claude label reads once.
   - **What stays behind.** 0.3.0 works with these left in place, and has no setup page:
     - the setup page's service files;
     - the `filament-kit-web` user and its folder;
     - the setup code.

     To remove them, run as root:

     ```bash
     systemctl disable --now filament-kit-setup.socket
     rm -f /etc/systemd/system/filament-kit-setup.socket /etc/systemd/system/filament-kit-setup@.service            /etc/systemd/system/filament-kit-setup-apply.service /etc/tmpfiles.d/filament-kit-setup.conf
     rm -rf /run/filament-kit-setup && systemctl daemon-reload
     setfacl -R -x u:filament-kit-web /etc/filament-kit /var/lib/filament-kit
     find /var/lib/filament-kit -type d -exec setfacl -d -x u:filament-kit-web {} +
     rm -rf /var/lib/filament-kit-web && userdel filament-kit-web
     rm -f /etc/filament-kit/setup_code /etc/filament-kit/setup_code.plain /etc/filament-kit/setup_lockout.xml
     ```

     Remove the user's file permissions (the two `setfacl` lines) before the user itself. If `slot_service.token_file` in
     config.json names a token file, remove that user's permission on it the same way. If you upgrade to 0.4.0 again
     later, removing `/var/lib/filament-kit-web` first makes the upgrade copy the web app's current files again.
