# filament-kit 0.4.3

Upgrade the server with `sudo filament-kit update`.

## What's new

### A tabbed setup page

The setup page (`https://<computer name>.local:8710/setup`) now has tabs: **Overview**, **Modules**, **Printers**,
**Devices**, **Settings** and **Updates**.

- **Overview** shows the version, what the checks of `sudo filament-kit status` say, and a **Still to do** list. Addresses
  and serial numbers stay hidden until you give the setup code and tap **Show addresses**.
- **Modules** has ready-made modes, with what each will switch on, and a live log while the change is applied.
- **Updates** shows the latest release and its notes. **Check now** (with the setup code), **Update** and **Roll back**
  work from the page. The page waits through the restart and reloads itself when the update is done.

### Smaller changes

- **Undo** refuses a spool that was not there when the print ended.
- **Turning a module off** says everything it takes with it, and a terminal offers what one needs.
- **A signed filament library with newer rules** is used without what this kit cannot read, and says how much.
- **Printers tab.** Both printer families are added, renamed, moved and tested from the setup page. Every address takes an IP address or a name (DNS or `.local`), kept as you typed it; a Klipper printer is never asked for an Access Code. An address outside the home network is saved with a note saying why it shows offline and what allows it. A scan knows a printer you added by name. A running slot mapping shows its progress and Stop again after a reload.
- **Trusted computers.** After the setup code worked once, a browser can be trusted so it is not asked again, for 90 days after its last use; **Devices** lists, renames and revokes them, and a switch turns the feature off. A new setup code keeps them trusted and says so; `sudo filament-kit setup-code --revoke-trusted` forgets them.
- **Slot mapping.** A calibration job that ended as a failure is reported as one, with what the printer said, instead of as an unknown numbering; a job the printer ends FAILED with no error is a finished job, as before.
- **Klipper.** A scan keeps to networks the server can reach, one printer is one entry (no twins from discovery), a tag scan is recorded against the active tool, and a tap made while the kit was not running is reconciled as soon as it connects.
- **Release.** The release script gives a tarball built by hand the same app version code as the workflow, so every release's app is an upgrade; Add's result lines read as sentences.
- **Klipper printer pack.** It offers a restart of Moonraker after editing `moonraker.conf`, only while the printer is
  idle, and asks for the Spoolman address and says so when it has none.

## Upgrading

Run `sudo filament-kit update`. Going back to the previous version (`sudo filament-kit update --rollback`) leaves the
setup page's new job unit on disk, unused.
