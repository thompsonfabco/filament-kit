# filament-kit 0.4.3

Upgrade the server with `sudo filament-kit update`.

## What's new

### A tabbed setup page

The setup page (`https://<computer name>.local:8710/setup`) now has tabs: **Overview**, **Modules**, **Printers**,
**Devices**, **Settings** and **Updates**.

- **Overview** shows the version, what the checks of `sudo filament-kit status` say, and a **Still to do** list. Addresses
  and serial numbers stay hidden until you give the setup code and tap **Show addresses**.
- **Modules** has ready-made modes, with what each will switch on, and a live log while the change is applied.
- **Printers** covers both families. Add a printer by type: a Bambu Lab printer takes its serial number and Access Code;
  a Klipper printer never asks for an Access Code. An address can be a name or an IP, and is kept as you typed it; an
  address outside the home network is saved with a note saying why it shows offline and what allows it. Printers can be
  renamed, moved and tested from the page. **Scan** and **Detect** look for printers, and a scan knows a printer you
  added by name. The printer-pack commands for a Klipper printer can be run from the page, and **Map slots** shows its
  progress and has a **Stop** button, also after the page is reloaded.
- **Devices** lists the computers you trusted. After the setup code works once, the page offers **Trust this computer**;
  that browser then needs no code for 90 days after its last use. Each entry has **Rename** and **Revoke**, and there
  is **Revoke all** and a switch that turns the feature off and forgets them all. A new setup code keeps trusted
  computers trusted; `sudo filament-kit setup-code --revoke-trusted` forgets them, alone or with `--new`.
- **Updates** shows the latest release and its notes. **Check now** (with the setup code), **Update** and **Roll back**
  work from the page. The page waits through the restart and reloads itself when the update is done.

### Android app

- **Back** goes one step back on the pairing screens, not out of the app.
- **A light and a dark theme**, following the phone.
- **Slot mapping** results say each thing once and say what to do next. A filament colour has a black ring so a dark
  colour stays visible on a dark background, and an empty slot is a dashed ring.
- The first screen shows both versions: **App x · Server y**. The connection dot is calmer.
- The first pairing screen has the switch that skips the fingerprint check.

### Klipper printers

- **One printer, one entry.** Adding a name or address that resolves to a printer you already added is refused, and the
  message says which. A discovery twin of a printer added by name is removed, display names are kept apart, and at most
  32 unconfigured entries are kept.
- **A scan through the server** only tries address ranges the server can reach, one at a time, and says when it refuses
  one.
- **A tag scan** is recorded against the tool that is active, on a multi-tool printer. A tap made while the kit was not
  running is reconciled as soon as the kit connects.
- **`loadtemp`** says when the printer's own macro will not trigger it.
- **A refused `klipper_hardware.xml`** fails `sudo filament-kit status` and shows on the printer's page. The
  `migrate-ops` dry run changes nothing.
- **The printer pack brings the spool macros** when a reader is installed.

### Smaller changes

- **A failed slot-mapping job** is reported as a failure, with what the printer said, not as "unknown numbering"; a job
  the printer ends FAILED with no error counts as finished, as before. The map view names the program that ran the job.
- **The result of Add spool** reads as a sentence.
- **Undo** refuses a spool that was not there when the print ended.
- **Turning a module off** says everything it takes with it, and a terminal offers what one needs.
- **A signed filament library with newer rules** is used without what this kit cannot read, and says how much.
- **Klipper printer pack.** It offers a restart of Moonraker after editing `moonraker.conf`, only while the printer is
  idle, and asks for the Spoolman address and says so when it has none.

## Upgrading

Run `sudo filament-kit update`. Going back to the previous version (`sudo filament-kit update --rollback`) leaves the
setup page's new job unit on disk, unused, and the file of trusted computers (`/etc/filament-kit/setup_trusted.xml`)
stays too, which the earlier version ignores.

The library in this release is filament-library 219fb46, the same as 0.4.1 and 0.4.2.
