# filament-kit 0.5.0

Upgrade the server with `sudo filament-kit update`.

## What's new

### The setup page

The setup page (`https://<computer name>.local:8710/setup`) gains **Presets** and **Logs** tabs, and most of what you
used to do in a terminal can now be done on it.

- **Devices** says "Paired: <name>" when a phone or computer you were pairing shows up. **Pair the station on this
  machine** pairs the intake station that runs on the same computer, with nothing to paste. With the web part on, it
  also shows the address of the phone web app and a QR code that leads to it (the iPhone card).
- **Stations asking to pair.** A station on another computer can ask to pair from its own screen: it shows six digits and
  says them. **Show requests** lists the stations asking; tap **Pair** only if the page shows the same six digits, or
  **Refuse**.
- **Presets** shows the last preset build, with **Build now** and **Restore deleted presets**. **Show what would be
  accepted** lists the pending preset updates and **Accept these** accepts exactly that list. Nothing else there replaces
  a preset in your slicers.
- **Logs** shows the last lines of one service of a module that is on. Logs hold addresses and serial numbers, so
  reading one takes the setup code.
- **Settings** now has **General** (display name, storage locations, the Claude model, reads per day, the station's
  voice), an address for an external Spoolman (saved only after the server has reached it), the remote certificate when
  the remote module is on, and a **Filament library** card: version, source and last check, **Update now**, going
  back, and a box for an entry of your own.
- **Backups.** A whole-kit backup is one zip file: **Back up now**, download it, and **Restore** it, also onto a
  freshly installed machine. A restore checks every file first and refuses a backup made by a newer version. The user
  guide has the steps.

### Mapping slots by hand

When **Map slots** keeps failing, the **Printers** tab offers **Map by loading filament**. It names one slot (or, for a
Klipper printer, one tool or lane) at a time, you load it, and you confirm what the printer reports. Mapping by hand does
not turn on filament use by itself; that still waits for **Map slots** to prove the numbering. A map view that stopped
midway now says why, in a sentence.

### Klipper printers

- **One printer, one entry** on every path: the setup page, the API and the terminal refuse a second spelling of a
  printer you already added.
- **`klipper add`** says when the printer cannot be reached, keeps a name that does not resolve with a note (the printer
  may just be off) and refuses what cannot be an address.
- **A printer whose Klipper is down** now reads as down, not as a finished job, when Moonraker refuses the subscription.

### Installing and updating

- **The installer says what to do next.** Every "run `./install.sh` again" names the real install line. A failed
  download says so, a computer without systemd stops with a sentence, WSL gets a note, and when `ufw` is on the end of
  the install prints the `sudo ufw allow` commands for the ports the modules need (it prints them; you open the ports).
- **A stopped install says the one command that repairs it**, on the terminal and on the setup page's Overview.
- **Updates that do not start fail clearly.** With no terminal (the setup page, a script), a kit server that does not
  answer for 120 s after an update fails the update, and the updater puts the earlier version back. At a terminal the
  wait is still 30 s and `sudo filament-kit status` says what is wrong.
- **A rollback removes the unit files** the version it leaves introduced, so going back no longer leaves them behind.
  Rolling back from v0.4.3 itself still leaves the setup page's job unit on disk, unused.

### Phones, the web app and pairing

- **A client can revoke its own pairing** (`DELETE /api/pair`), and only its own.
- **The web part's token reaches only the routes the web part calls.** Every other route now refuses it. An existing
  web part needs no new pairing.
- **A station on another computer pairs from its own screen**, as above; it saves its pairing by itself within a few
  seconds.
- **`sudo filament-kit reader setup --source <checkout>/reader`** sets up a bench NFC reader plugged in by USB: it makes the
  token, asks the Wi-Fi name and flashes the reader. It needs your own PlatformIO.

### Android app

- **Slot mapping shows the server's outcome.** The result of a mapping says what happened and the next step, in the
  server's sentences, and offers the step its reason calls for: map again when the printer or the kit was in the way, or map by loading
  filament when the calibration proved nothing.
- **Map by loading filament** is in the app too: it maps a printer one position at a time, as the setup page does.
  A map made this way after a failed job is the current map.
- **Updating the app shows its progress.** The download reads "Downloading… 40%" when the server gives the size, and
  plain "Downloading…" when it does not.

### Camera relay

The camera relay moves video both ways on one thread, and what ffmpeg sends just before it stops still reaches the
printer, so a stopped stream ends cleanly.

### Nightly prereleases

Every night at 23:00 New York time, a prerelease is built from the `nightly` branch for people who want to try things
early. It is built without tests, **unsigned** (a plain `SHA256SUMS`), and installed kits are not offered it. Its app
installs beside the stable one as **Filament Kit Nightly**. The stable releases are unchanged.

### Station hardware

Build guides, wiring and enclosures for the station's devices are moving to the separate filament-kit-hardware repository (https://github.com/thompsonfabco/filament-kit-hardware).
Until that split lands, the panel's wiring, build and flash steps stay in `station/PANEL.md`.

## Fixes

- A Klipper load's wait still ends when the connection drops and comes back between two looks.
- Maintainers: flaky tests fixed (the reader's scan deadline and stop tests, three Klipper tests); the library folder of
  `make_release.sh` defaults to beside the checkout.

## Upgrading

Run `sudo filament-kit update`. `sudo filament-kit update --rollback` now removes the unit files of the version it leaves
that the earlier version does not have. A rollback started from v0.4.3 itself still leaves the setup page's job unit on
disk, unused.
